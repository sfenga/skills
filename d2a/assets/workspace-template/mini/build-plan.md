# Mini 构建计划与记录

只实现构建计划中的首个可运行切片。优先得到小而可执行的结果，不扩大范围；技术栈在可行时与原项目保持一致。可以少实现功能，但不得通过合并模块、反转依赖或迁移状态所有权来减少代码。

## 三道 Gate

填写 `mini/gates/build.json`：说明 Provider 模板与技术栈是否命中、构建 Timebox 与降级方案，以及源码必须证明的 Intent 锚点。

## 构建顺序

列出使单一主路径尽早运行的最少步骤。每一步写明目标、涉及文件和可验证完成信号。

## 实际实现

记录实际新增或修改的文件、入口、运行命令、退出码和可观察输出。若实现现实迫使设计修正，明确记录修正及原因。
同样的信息必须写入 `mini/build-evidence.json`；源码路径必须真实位于 `.d2a/mini/source`，且不能只提供 README。
同时为 `mini/architecture-alignment.json` 中每个职责映射、调用方向、状态所有权和边界语义补充真实 Mini `文件::符号` 证据。

## 刻意未实现

首个可运行切片稳定后，简要记录仍刻意未实现的内容，以及它们为何不影响架构意图验证。
