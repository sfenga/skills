# Mini 测试

从首个可运行切片的一条端到端测试开始，优先验证可观察行为而不是内部单元细节。首个场景明确后，只补充下一个最有价值的失败场景；两者都必须验证选定的架构意图。

## 三道 Gate

填写 `mini/gates/test.json`：说明 Provider 测试契约是否命中、测试 Timebox 与降级方案，以及测试要证明的 Intent 锚点。

## 首个集成测试：成功主路径

记录测试目的、输入或前置条件、真实命令、期望行为、实际结果、退出码和可观察的成功信号。

## 下一集成场景：失败路径

记录最有价值的预期失败：故障如何注入、真实命令、期望失败行为、实际结果、退出码，以及可观察的失败信号。失败必须被确实观察到，不能只写测试计划。

## 架构意图验证

说明成功与失败场景分别证明了哪个对象、状态或协作链锚点，并将真实执行证据同步写入 `evidence.json`。
同时复核 `mini/architecture-alignment.json`：测试信号应经过与完整版本相同职责的组件边界，失败也应由相同边界负责处理，不能只证明最终输出相似。
